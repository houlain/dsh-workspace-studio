# 0.3.0 修复契约（红队 32 条裁决后的统一规格）

本文件是并行修复的**唯一契约**。任何实现与本文件冲突时，以本文件为准；若本文件本身有问题，先在 `docs/` 里改它再改代码。

## 0. 目标与非目标

- 目标：修掉红队清单 P0/P1/P2 全部 32 条，保持既有功能（文件树/预览/diff/逐块撤回/逐块认可/一键同意/清空）行为不变或更安全。
- 非目标：不新增功能（除契约内明确的 UX 兜底），不改 UI 视觉设计，不做跨平台（仍只保证 Windows + DSH 0.2.1-rc.5）。
- 版本：`0.3.0`。

## 1. 统一路径口径（`canonicalPath`）

`src/host/security.ts` 导出：

```ts
export function canonicalPath(p: string): string | undefined  // 非绝对路径返回 undefined
```

规则：Windows（`process.platform==='win32'` 或形如 `C:` / `\\`）用 `win32.normalize`，统一转 `/`，折叠大小写；否则 `posix.normalize`。去掉尾部 `/`。**台账比较、路径授权、去重、分桶全部用它可以拿到的同一口径**；展示用原串。

破坏性变更：`src/core/ledger.ts` 的 `filePath` 桶、`removeOpsForFileInSession`、`pruneFile`、`service.opsFor` 的相等比较，全部改成 `canonicalPath(a) === canonicalPath(b)`。

## 2. 路由契约（`/api/dsh-workspace-studio/*`）

| 路由 | 方法 | 信任要求 | 说明 |
|---|---|---|---|
| `/tree?root=` | GET | **需信任** | root 必须在允许根内 |
| `/file?path=` | GET | **需信任** | 路径在允许根内，且不命中敏感名单 |
| `/ops?session&file?` | GET | **需信任** | 不带 file 时：逐条过滤，**只返回允许根内的文件**；不允许整份回吐 |
| `/context?session=` | GET | **需信任** | 返回 `{cwd}`；取不到时返回 `{cwd: null}`（不要空对象） |
| `/events` | GET SSE | 不要求（EventSource 不能带头） | **载荷去掉 sessionId**，只发 `{"changed":true}`；客户端自行刷新当前会话 |
| `/revert?session=` | POST | 需信任 | body `{path, opId?|op?, hunk?, opId?}` — 见 §3 |
| `/accept?session=` | POST | 需信任 | body `{path, opId, hunk}` |
| `/accept-all?session=` | POST | 需信任 | body `{path}` |
| `/clear?session=` | POST | 需信任 | |

统一响应：`{ok:boolean, ...}`；错误必须带 `error` 字符串。所有 handler 必须 try/catch。

**信任判定**（`isTrustedRequest`）收紧：
- 必须有 `x-dsh-workspace-studio: 1`；
- `socket.remoteAddress` 必须是**回环 IP 字面量**（`127.0.0.1`/`::1`/`::ffff:127.*`）；`localhost` 只在 Host/Origin 里出现时可接受，但 `127.evil.com` 这种**主机名一律拒绝**（当前实现的前缀判断是 bug）；
- 若有 `origin`：必须 `origin.host === host`，且 origin 主机是回环 IP 或字面量 `localhost`；
- 若有 `sec-fetch-site`：必须 `same-origin`；
- 说明：这挡得住跨站页面与 DNS rebinding，挡不住本机任意进程——README 必须如实写清楚，不得再声称"本机其它进程够不到"。

**敏感路径拒绝名单**（读+写都套）：路径任一段命中 `.secrets`、`.env`、`.env.*`、`*.key`、`*.pem`、`id_rsa*`、`credentials*`，或位于 `~/.dsh` 下 → `403`，错误信息说明"该路径被插件策略拒绝"。

## 3. 操作身份：`opId` 取代下标

- 路由 body 接受 `opId: string`（稳定 uuid）。**`op`（下标）保留兼容但仅在同时提供 `opId` 时不使用**；新客户端只发 `opId`。
- `service.revertHunk/acceptHunk` 签名改为 `(sessionId, filePath, opId, hunkIndex)`。
- 服务端按 `opId` 在 `opsForSession(sessionId)` 里查找，找不到返回 `{ok:false,error:'该操作已过期或被清理，请刷新'}`。
- 服务端必须**先校验该 hunk 是否已 reverted/accepted**：`revertHunk` 也要查（当前只有 `acceptHunk` 查）。

## 4. 整文件撤回的基线策略（修 P0-2）

`revertFile(sessionId, filePath)`：

1. 取该文件全部 op（canonical 比较），按 `ts` 升序；
2. **基线 = 最早一条仍带内容快照的记录**：`before` 为字符串 → 用它；`before === null && created === true` → 删除语义；`before === ''`（超大占位）→ 跳过继续找更晚的记录；全部跳过 → `{ok:false,error:'原始内容快照已被清理，无法安全撤回'}`；
3. **裁剪防护（0.3.0 追加，Lead 复现后补）**：台账必须记录「该文件的历史曾被容量裁剪」（`ledger.wasPruned(filePath)`，随 state 一起持久化）。若基线是 `created === true` 但该文件 `wasPruned` 为真 → **一律拒绝删除**，因为裁剪会丢掉"文件在会话开始时原本存在"的证据，此时一条 create 记录可能只是"删除后重建"的中间态。已复现：不设此防护时会删掉会话前已存在的文件且原内容不可恢复。
4. 只有基线是 `created===true` **且未被裁剪** 才允许删除；且删除前必须 `isPathInsideWorkspace(filePath, [sessionCwd])`（沙箱根），不满足则拒绝；
5. 写入带版本意图（§5）；
6. 成功后再清账，且清账用 `canonicalPath` 匹配（修 P1-15 / 反例 4）。

## 5. 写到宿主的契约（修 P0-7 / P1-8 / P1-11）

- **写**：`writeText(target, content, expected, signal, policy)`，其中 `expected` 必须是 `{ kind: 'replaceIfVersion', version }`（`FsWriteIntent`），**不是裸 version**；无版本时传 `undefined`（表示无条件写）。
- **删**：宿主 `ctx.fs` **没有** `remove(target)` 动词（只有 loader/任务服务的 `remove(id)`）。因此：
  - 若 `fs.remove` 存在（未来宿主）→ 用它并传 policy；
  - 否则用 `fs.processPath(target)` + `node:fs/promises.unlink`，但**必须先通过** §4 的沙箱根校验；不满足直接拒绝，不做裸删。
- `types.ts` 的 `FsLike` 增加 `writeText(target, content, expected?: FsWriteIntentLike, signal?, sandboxPolicy?)`；`remove?` 保留为可选（未来兼容）。

## 6. hunk 撤回定位（修 P0-6）

`src/core/hunkRevert.ts` 改为**位置优先 + 上下文校验**：

1. 先按 `newStart`（±2 行）在目标位置找匹配；
2. 校验该位置的 `ctxBefore`/`ctxAfter` 与文件实际行**逐行相等**；
3. 不匹配则在全文搜索；**只有唯一匹配**才应用；
4. 多个匹配或无匹配 → 返回 `{ok:false, reason:'无法唯一确定该变更块的位置（文件已被其它修改影响），请刷新后重试'}`，**绝不猜测**。

## 7. 台账（`src/core/ledger.ts`）

- `LedgerOp` 增加 `truncated?: boolean`（原 `before=''/after=''` 的占位必须置 true，UI 显示"快照过大，不可撤回"，不再把空文件与占位混同）。
- `load()`：`isValidOp` 严格化（`revertedHunks`/`acceptedHunks` 必须是 number[]；`created`/`truncated` 若存在必须是 boolean）；被丢弃的记录数写入日志，并把原文件另存 `*.dropped-<ts>` 后再继续。
- **用户动作必须落盘**：`revertHunk`/`acceptHunk`/`acceptAllHunks`/`revertFile`/`clearSession` 成功后调用注入的 `persist()`（`index.ts` 传 `scheduleSave`）。
- 保持：全局 2000 条、每文件 100 条、120KB/条、fsync+随机 tmp。

## 8. 客户端（`src/client/*`）

- `apiJson` 必须检查 `res.ok` 与载荷 `ok === false`，抛错；调用处 catch 后写 `error` 状态。
- 所有请求带 `x-dsh-workspace-studio: 1`（读也带）。
- 撤回/认可改为传 `opId`（`OpView` 增加 `id` 字段，服务端下发）。
- **切会话必须重置** `selected/content/ops/root/notice/error`；`loadSelected` 用自增序号丢弃过期响应；SSE 不再按 session 过滤（载荷无 session）。
- `FileTree`/`DiffPanel` 对 `tree`/`ops` 做形状校验（`Array.isArray` / `ops?.files?.length`），不因错误包崩溃。
- 空态与错误态必须有可读文案（"树加载失败，点 ↻ 重试"等）。

## 9. 测试（`tests/**`，不参与构建）

必须新增/修改：
- 槽位契约：`label()` 返回**字符串**；`register` 的 render 被边界包裹（桩需支持类组件与 `getDerivedStateFromError` 语义，至少显式断言包裹层存在）。
- `canonicalPath`：大小写、`\`/`/`、`.`/`..`、重复分隔符、尾部斜杠。
- 基线策略：裁剪后仍能撤回（不删非本会话文件）；占位记录被跳过；无快照时拒绝。
- 写意图：断言传给 `writeText` 的 `expected` 是 `{kind:'replaceIfVersion',version}`。
- 敏感路径：`.secrets`/`.env`/`*.key` 一律 403。
- opId：过期 id 返回明确错误；重复撤回被拒。
- hunk 定位：多处同内容 → 拒绝；上下文不符 → 拒绝。
- 用户动作落盘：`persist` 被调用。
